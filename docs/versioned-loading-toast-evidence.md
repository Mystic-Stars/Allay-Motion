# 版本化加载与提示：证据总览

详细的取样、尺寸、资源路径和局限分别见 [Java 加载](fidelity/java-loading.md)、[Java 进度与成就提示](fidelity/java-toast.md)、[1.21.1 原版绘制记录](fidelity/java-vanilla-reference.md)、[基岩加载与成就提示](fidelity/bedrock.md)。另外六个内置模板是原创转场或创作工具，其[控件核查](fidelity/original-template-controls.md)不属于游戏画面还原。版本名表示参考样本或兼容档，不表示整个版本范围、所有图形设置或各平台均已逐帧核对。

## 当前实现

| 模式 | 实现与所依据的证据 |
| --- | --- |
| Java 启动／资源重载 | 旧白底与 1.21.1／26.3 红底使用对应字标贴图和 GUI 条几何；缺字标就省略，不绘制替代字标。原版 JAR 可核对背景、布局和淡化常数；实际 I/O、上一屏重绘及驻留策略不由模板模拟。 |
| Java 世界载入 | 1.14 初版与 1.14.1 起的旧泥土档区分 45／43 格；1.21.1 参考档用真实全景资源、29 格与百分比；1.21.9 和 26.3 参考档用 35 格、状态文字和水平条，26.3 单列且采用该版状态色序。区块状态与进度是演示时间函数，不来自游戏存档。 |
| Java 跨维度 | 旧档用泥土；1.21.1／26.3 的经下界档用门户动画贴图，经末地档用对应版本的两张纹理和 15 层屏幕投影，其他路线用全景；不加虚构进度条。末地的起始世界刻由片段设定，并非读自玩家的世界；全景模糊压缩了原版滤波采样，不能据此声称两版画面逐像素相同。 |
| Java 成就／进度 | 旧成就从顶部移入，使用成就图集；经典进度从右侧移入，优先旧 `toasts` 图集，可用独立 sprite；26.3 用独立 sprite。三者为 160×32，按年代使用已核对的动效、文字换段与音效触发。固定单弹窗，不模拟原版队列；自定义时长、图标和音效仍可用。 |
| 基岩加载 | Windows 26.63 的灰底启动是待采样参考；世界载入、世界资源包加载和三条目的地路线以官方 26.60 样例为依据。支持普通资源包的标题、全景、面板、往返帧和确定进度资源；跨维度档用目的地方块背景。阶段和轮换提示不代表实际加载时间。 |
| 基岩游戏内成就 | 26.60 样例的顶部居中提示，使用面板与可绑定图标；样例引用的图标可能实际缺失。此模式不是 Xbox 通知或 PlayStation 奖杯，不表示已在 Windows 或所有设备上观察到该提示。 |

旧工程和空预设继续按 manifest 进入 `generic`；显式新建另按绑定资源选择已声明的版本档。两者不要混淆。例如 Java 1.20.4／1.20.5 分别选择泥土与全景，1.21.8／1.21.9 分别选择百分比与条，26.3 使用独立档；未知版本和快照不冒充匹配。基岩 1.21.0 的新建配方是场景选择规则，不是 1.21.0 真实画面证据。自动文案语言跟随应用语言而非猜测输入文字。

版本模板只访问授权资源栈，不自行下载。宿主可读取经过校验的同版本索引贴图和白名单内的 Unihex 字库定义、归档；缺失时退回 JAR 或内置字体。Java 全景需要有效六面，JAR 内的 1×1 占位不算命中。已缓存但缺字库或全景的版本可在「设置 → 素材」中重新下载该版本；预览和导出不会自行联网补齐。基岩合成与用户的普通未加密资源包走同一模板资源 ID；不读取加密包 UI 脚本。

## 核验到哪一层

- **文件与运行数据**：Java 原版 JAR、官方映射、资源索引和 PNG／OGG 元数据支撑资源与布局核对；26.3 提示另用无窗口 JVM 实际采样原版位移类。基岩 Windows 26.63 仅核对可访问文件、文案和安装版本，布局参考 26.60 官方样例。均未把原版文件放进测试夹具。
- **1.21.1 独立对照**：离屏执行原版进度提示绘制方法，记录背景、文字、图标、位姿、音效投递和计时，不使用模板生成参考值。应用在经校验的同版中文字库下回读 480×270 静帧，短标题与名称的明亮像素分别在 `y=7…14` 和 `18…25`。长挑战名称按原版两行显示，切换时刻 2.100 s 没有可见文字，到 2.400 s 两行均可见。另由实际 PNG 序列导出 373 帧（60 fps，包含透明端点），第 144 帧解码 RGBA 与同设置、同时刻的应用静帧逐字节相同。这最后一项是导出一致性验证，不是与游戏帧缓冲的比较。
- **合成场景**：`T-TPL.loading-progress.test.ts` 调用真实模板入口，验证版本与资源绑定、默认判定和模拟曲线；基岩成就不再通过 Java 查表测试。配合三个 `T-FID` 场景测试与新建配方测试，可检查 Three 场景、参数及数据，但不是 GPU 帧结果。
- **应用 WebGL**：`T-TPL.versioned-loading-and-toast.spec.ts` 保留三画幅的旧像素基准和原误差阈值；新版使用独立的程序生成纹理，验收资源请求、透明首尾、不透明剪辑点、乱序逐帧一致、真实缺图告警，以及背景区域和进度区域的独立变化。该测试的运行结果以本次 Electron 执行日志为准；合成纹理或旧基准都不能证明新版与游戏画面等同。
- **本轮集成验收**：15 项引擎专项和 7 项原生窗口用例通过。覆盖全部八个内置模板的相关引擎路径、旧像素基准、末地 15 层合成、基岩进度填充与背景冻结，以及自动标题、自定义标题、预设恢复和代码初始化／逐帧追踪。其中 3 项标题相关窗口用例还在最后一次语言修正后重新通过。
- **实物资源的应用取帧**：2026-11-18 在独立数据目录逐项校验 Java 26.3 官方全景对象并绑定对应版本，离线用 Windows 桌面应用的静帧 Worker 渲染了启动、世界载入、下界切换、进度提示四个场景，各三帧。进度提示的三个横坐标与同版本原版 JVM 运行值相符；世界在 0.40、0.75、1.05 秒用了真实六面，取帧时均未产生缺图告警。当天六项版本模板 WebGL 回归亦通过，包括旧三画幅基准和缺图路径。未把含官方素材的帧加到仓库。
- **仍欠证据**：没有绑定具体版本、设备、GUI 设置和时间码的实际游戏录屏对照，也没有现场原声与剪辑软件回读。优先采集 Java 1.20.4／1.20.5、1.21.8／1.21.9、26.3 的关键场景，以及基岩 Windows 26.63 启动／世界载入和确实能产生游戏内成就提示的设备；不把这些录制素材提交到仓库。
