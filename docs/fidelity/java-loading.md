# Java 加载界面：依据、样本与边界

本页取代 `docs/versioned-loading-toast-evidence.md` 里旧的 Java 加载界面描述。未启动游戏或登录账号。用本机两版 JAR 的类、着色参数、PNG 尺寸和色值，按官方映射和 `javap -c -p` 核对可见行为；仓库只留独立实现和数值预期，不留游戏程序、GLSL 源、原图或截图。本轮不是实际游戏逐帧录制。

## 末地投影与全景复核

- **末地调用链**：1.21.1 `ReceivingLevelScreen` 通过 `RenderType` 选 `end_portal`，在 JAR 内的 `assets/minecraft/shaders/core/rendertype_end_portal.json` 取层数 15；26.3 `LevelLoadingScreen.extractBackground` 调用 `RenderPipelines.END_PORTAL`，该管线也是 15 层，16 层 `END_GATEWAY` 不是这张屏幕。26.3 `GameRenderer` 在 GUI 前绑定 `FogMode.NONE`，不应额外套世界雾。两版取同一组 15 个颜色权重，叠加底层末地天空；两张输入图为 `environment/end_sky` (128×128) 和 `entity/end_portal`（1.21.1）或 `entity/end_portal/end_portal`（26.3，均 256×256）。GUI 齐次坐标 `w=1`，用归一化屏幕坐标，不受画幅宽高比或世界深度再缩放。原版采样为环绕最近邻；叠加计算在显示 RGB 域，提交到引擎前转为线性。例：归一化位置 `(0.25,0.75)`、时钟 `3000/24000`，第 1、8、15 层包裹前 UV 分别为 `(8.658234,3.858667)`、`(3.208170,0.378317)`、`(1.004167,1.937500)`。第 15 层权重 `(0.204675,0.390010,0.302066)`，相位每秒只移动 `0.0075` 个纹理周期，而不是旧实现的两个平移滚动层。
- **末地时钟**：1.21.1 `RenderSystem.setShaderGameTime` 用 `(worldTick % 24000 + partialTick) / 24000`，由世界渲染入口更新。26.3 `GlobalSettingsUniform.update` 同样归一化；`GameRenderer` 没有渲染世界时给它传 0 刻和 0 子刻。真实起始世界刻、是否在整个等待期间提交世界画面并不是 PNG 能证明的。本模板提供明确的 `javaEndStartTick`，默认 0；背景动效开启时按 20 刻/秒模拟活动世界，关闭时钉住所选刻。可用起始刻 0 并关动效模拟零时钟等待画面。未从游戏实录校准某次维度加载前后传入的刻值。
- **全景与菜单模糊**：1.21.1 `CubeMap` 的四次贡献由 `(-1/512,-1/512)`、`(0,-1/512)`、`(-1/512,0)`、`(0,0)` 的视空间位移及依次绘制的 255、127、85、63 alpha 得出。26.3 `CubeMapTexture` 的上传顺序 `1,3,5,4,0,2` 对应 `+X,-X,+Y,-Y,+Z,-Z`，上传时翻转源图行。1.21.1 的 `shaders/post/blur.json` 中两组 `RadiusMultiplier` 写在 `BlurDir` 条目上；`gfc` 的解析只读取该条目的 `name` 和 `values`，因此各道倍率实际沿用着色程序默认 1。26.3 `post_effect/blur.json` 六道的半径为 0 表示取 `MenuBlurRadius`，两版 `Options` 默认 5。三轮横纵盒式滤波折叠后，每轴支撑为输出像素 `−15…15`，中心权重 `91/1331`、方差 `30 px²`。模板每轴压成 5 个分组质心，保持权重和分组一阶矩，不复现中间缓冲量化、每道边缘钳制、立方体硬件跨面过滤。末尾再合成菜单贴图；全景遮罩在滤波前合成。

## 加载控件审计

| 路径 | 生效的背景与进度设置 |
| --- | --- |
| 通用 | 原方块、亮度、格宽和条色；旧默认及像素路径不改。 |
| Java 白／红启动、重载 | 显示进度、Java 条色；红底档可切黑。字标继续由资源层提供。 |
| Java 泥土世界 | 百分比开关和字体；使用固定版本底板或告警回退，不暴露通用泥土调色。 |
| Java 全景世界／其他维度路线 | 全景模糊、转速、动效开关；世界单独依版号显示百分比字体或条色，其他维度路线没有进度控件。 |
| Java 下界／末地／旧泥土跨维度 | 下界和末地可冻结背景，末地另外提供起始刻；旧泥土无动效；三者均无进度控件。 |
| 基岩启动／资源包／世界／各维度 | 各档可绑定标题图和背景。仅资源包／世界默认走全景并显示背景动效，绑定静态图时不会旋转。启动有百分比字体，启动／包／世界有进度开关；三个跨维度没有。条色和文字颜色不暴露给未接线的基岩渲染。 |

所有路径保留原进出时间、剪辑点和样式。随机种子仅影响溶解。Java 标题、副标题和填充色分别选择「原版」或「自定义」；原版模式不显示无效的输入框，自定义空串不画文字，显式自选 `#00000000` 不画有色填充。切回原版保留自选值。只在读取缺少来源标记的旧数据时，才按旧默认文案和填充色解释；旧透明黑继续表示自动。字号只作用于文字，不改变进度条和区块的坐标。

### 第 18 帧：完整资源与缺资源分别验收

2026-11-18，用同一份已校验的 26.3 客户端、简中字库、1920×1080 工程、60 fps 和默认 0.30／0.90／0.30 秒，分别构造完整六面和缺六面的离线测试目录。每一组都先打开「进度提示」取第 52 帧，再打开「加载界面」取第 18、45、72 帧；切回进度提示再回到加载界面，未带入另一模板的资源提示或改变同一帧的画面。只验证文件存在或只测其中一张模板不满足此验收。

- 原版 `LevelLoadingScreen` 在有区块视图、服务器进度为零时的[独立绘制参考](java-loading-frame18-reference.md)：中文「加载地形中…」的绘制原点 `(214,74)`、宽 53 GUI 像素，带阴影；黑条顶线为 `y=86`，此刻绿段宽为 0。未知状态的区块也为黑色，这两处不代表全景丢失。
- 应用在同一工程的 960×540 静帧上回读，修复前开关进度条会抹掉 180 个白色文字像素；修复后为 **0**。完整字库下，第 18 帧正文可见边界为 `(428,148)–(531,163)`（含端点，输出像素），条在 `y=172…175`。第 45 帧已出现绿色填充。
- 完整六面可用时，实际预览显示全景，没有缺图提示；只有 1×1 占位时，界面明确说明改用深色背景并提供素材设置入口，不在预览或导出中联网，也不把提示画进影片。实际导出的 91 张 PNG 中，第 18 帧解码 RGBA 和同输出尺寸的独立静帧逐字节一致。没有把本次资源、项目或图片纳入仓库。这不等于已对全景模糊或真实加载时序完成游戏录屏逐帧比对。

## 接入、验证与局限

- 已缓存 26.3 的用户可在「设置 → 素材」的版本库里选中已下载的 26.3，展开「重新下载此版本」并确认「下载所选正式版」；完成后使用这个已下载的版本。提取资源阶段会显示准备全景，只补该版本索引中存在的六面，复用已校验的 JAR、索引和对象。失败或取消不会留下半成品，重试会复用已校验文件。不含全景条目的旧版仍使用 JAR；预览、导出和切换版本不会下载全景。
- `ctx.resources.optionalTexture()` 只走已授权资源栈，版本样式不切换资源层、不找文件、不联网。缺六面中的任一面（包括 1×1 占位）就提示并改用深色；无字标就不画字标；泥土底板缺失可用资源栈的泥土方块并提示；缺维度图则用深色。已授权资源包可覆盖相同 ID。
- 宿主 `apps/desktop/src/main/resources/vanilla.ts` 优先读取与版本匹配、通过校验的本地索引贴图。初查时 26.3 缓存有索引但缺六面对象，1.21.1 安装目录也未找到索引。只有 JAR 时仍会读到 1×1，模板会告警。2026-11-18 的 Windows 桌面核验在**独立数据目录**补齐 26.3 索引 34 对应的六个官方对象，逐个核对 SHA-1、字节数和 1024×1024 尺寸，随后断开应用的联网路径。在 480×270 输出取 0.40、0.75、1.05 秒的帧：世界载入显示实际全景、区块图与进度条，三帧均不透明且图像不同；启动字标和下界动画也以对应版本的资源成功绘制。该流程没有更改原先的资源库，未验证 1.21.1 的真实六面或泛化到所有版本。
- 下界优先使用资源栈的动画 UV；没有元数据时只对精确的原版 `16×512` 尺寸应用已核对的 32 帧时序，其他尺寸的长图告警并静止在第一帧。
- 模拟曲线与区块状态只是编辑器片段时间的函数。没有人工曲线编辑或真实数据轨，不声称实际读盘、重载、加载世界或维度切换有固定耗时。`animateBackground=false` 冻结画面背景，不冻结显示进度。`generic` 默认及渲染入口不改；旧 Java ID 继续能打开，但采样画面随修正变化。
- 回归用例包括 `T-FID.java-loading.test.ts` 的 GUI 字形与阴影布局、`T-FID.loading-copy.test.ts` 的显式值和迁移、`panorama-fallback.spec.ts` 的缺图反馈和资源修复、`loading-controls.spec.ts` 的实际控件及预设恢复。集成构建通过 9 项版本化模板 WebGL 测试和 3 项原生窗口相关用例；未跑完整 `pnpm check`，未重做通用模板的像素基准。
