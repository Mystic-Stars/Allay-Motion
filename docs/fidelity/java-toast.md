# Java 成就与进度提示：实现依据

## 本机证据

- **26.3**：`%APPDATA%\AllayMotion\vanilla-cache\versions\26.3\client.jar` 的 SHA-1 为 `e877b6a07acd633fb3bb475002175cec036e7b87`，与缓存版本元数据一致。JAR 中确有具名的 `net.minecraft.client.gui.components.toasts.ToastManager$ToastInstance`、`AdvancementToast`、`Toast`。用 `%APPDATA%\.minecraft\runtime\java-runtime-epsilon\bin\javap.exe` 读取可观察的 GUI 参数、时间常数和音效调用点。另查 `ToastManager`、`Toast$Visibility`、`GuiGraphicsExtractor` 与文字片元的透明度阈值；未导入游戏实现。
- **1.21.1**：本机正版 `%APPDATA%\.minecraft\versions\1.21.1\1.21.1.jar` 的 SHA-1 为 `30c73b1c5da787909b2f73340419fdf13b9def88`。用本机版本 JSON 所指的官方 client mappings（校验 SHA-1）定位提示类，核对其行为与 PNG。1.21.1 和 26.3 的 `textures/gui/sprites/toast/advancement.png` 均为 160×32，SHA-256 均为 `15a959d338d8ce98c1381f95d34f7143377669bcadae1198900bea88144d6634`。

- **早期版本**：按本机启动器版本清单取 Beta 1.5、1.11.2、1.12.2、1.20.1 与 1.21.2 的官方元数据，临时读取 SHA-1 校验通过的 JAR。Beta 1.5 与 1.11.2 都使用 256×256 图集 `(96,202,160,32)`；路径分别是 `achievement/bg.png` 和 `assets/minecraft/textures/gui/achievement/achievement_background.png`。1.12.2 的 `AdvancementToast` 使用 256×256 的 `textures/gui/toasts.png`，裁区 `(0,0,160,32)`；1.20.1 仍有该图集。1.21.2 已换 `ToastManager`，但该版被查验的进度挑战音仍在全显后的首次正时间更新触发；不把所有中间版本视为逐版已实测。

## 模板行为

| 模式 | 锚点与原版节拍 | 原版音效事件 |
|---|---|---|
| `javaAchievement` | 右上；从 `y=-36` 沿顶部移入，使用整数 GUI 像素偏移；375 ms 四次曲线入场、2250 ms 停留、375 ms 四次曲线出场 | 查验的旧成就通知无专用提示音；不加现代进度音 |
| `javaAdvancement` | 右上；先探测旧图集，再探测独立 sprite；600 ms 滑入、5000 ms 全显、600 ms 滑出；进入可见比例为 `p²`，退出为 `1−p²` | `ui.toast.in` 在 0，`ui.toast.out` 在开始退出；挑战另在全显后首次正毫秒（固定采样模型为 601 ms）触发 `ui.toast.challenge_complete` |
| `javaAdvancement263` | 右上；独立 sprite；位移和默认时长与上述采样相符 | 入、出事件仍对应显示/隐藏切换；挑战事件在入队占位时播放。单弹窗时间轴把相邻的入队与首次入场更新合并为 0 ms |

- 固定 160×32，不用文本撑大面板。图标盒 16×16，左上 `(8,8)`；两短行无阴影，在 `x=30` 左对齐，原版 GUI 文字绘制原点 `y=7/18` 对应基线 `14/25`。读取 1.21.1 的 `SheetGlyphInfo`、`BitmapProvider` 与 `UnihexProvider`：位图顶线按 `7−ascent` 放置；Unihex 的采样倍率为 2，16 行源像素占 8 GUI 像素，基线上/下分别为 7/1，前进宽度为 `floor(源宽 / 2)+1`。混排共用基线，高清位图与 Unihex 保留源像素采样密度，而非把源尺寸当显示字号。普通/目标为 `#FFFF00`，挑战为 `#FF88FF`，名称白色。
- 进度名称按 125 GUI 像素的逻辑宽度换行。单行同显；多行先显示原点 `y=11` 的标题行，全显后 1200–1500 ms 淡出，1500 ms 切换，1500–1800 ms 淡入名称。名称首行原点为 `16−floor(行数×9/2)`，原版行距为 9 GUI 像素。模板给特殊字体留出上下框边：按字形的基线边界移动行，容不下时改用分段显示并将超出容量的名称加省略号；只对单行自身已超出可用尺寸的字形等比缩放。经典在整数 alpha 上执行 `| 0x04`，26.3 不加该位；模板按文字着色器的 0.1 阈值，将小于 26/255 的整行 alpha 视为不可见。
- Java 样式的「标题行」独立选择跟随类型或自定义。跟随时只显示预设语言；自动只使用应用的 `ctx.locale`，不根据名称猜测语言。自定义时只显示输入框，默认字面或空串都按输入处理；切回跟随保留输入。进度类型仍决定默认颜色与挑战音效，名称独立。缺模式时，旧 `header` 的空值和中英文默认文案仍表示跟随，其他非空文案迁为自定义；中间版非空 `javaHeader` 是字面值，即使与预设同文也保留。显式模式优先，包括自定义空串。旧 `generic` 与基岩样式不使用该开关。
- 不还原多弹窗排队、帧率和游戏渲染循环造成的毫秒偏差。模板按传入时间纯函数采样，并在首末各半帧隐藏，以满足透明端点。自定义时长继续使用原版位移曲线，按停留阶段的比例映射文字阶段；`javaTiming: auto` 保留旧工程非默认的时长，`vanilla` 忽略时长字段，`custom` 总是使用字段。`javaSound: auto` 保留非默认选音或静音，`custom` 可强制只播放自选音，`vanilla` 调度原版事件；音量仍可编辑。
- 贴图通过公开 `optionalTexture` 在资源栈内查找，候选未命中不报错；全部缺失才给出一条本地化提示，不画假面板。Beta 裸 JAR 的根路径不等于当前资源栈的纹理 ID；如普通导入无法解析，需要用户持有的资源包把对应图集放在 `assets/minecraft/textures/gui/achievement/bg.png`。不扩展旧资源包加载规则，不把旧图集跨代替换为新 sprite。原版音效 ID 通过现有资源栈解析，实际可听需当前启用的版本有对应音效数据。

## 验证边界

### 26.3 完整中文字库与后备字体的对照

对同一 1920×1080 工程、第 52 帧（60 fps）、第 0 槽、简体中文、GUI 缩放 4，以两个独立数据目录对比 26.3 素材：一个沿用缺少 Unihex 的旧缓存，另一个使用同版官方索引校验通过的字库。切换「Java 经典进度」与「Java 26.3」不会改变这一帧的默认钻石和两行短文字。缺库时，主预览的属性面板明确提示有字形使用内置像素字体；完整字库实际覆盖全部文字时，不提示回退。要为原有缓存补齐字库，在「设置 → 素材」中选中已下载的 26.3，展开「重新下载此版本」再确认；正常播放不会发起下载。

原版 JVM 的 GUI 绘制记录与字形提供器见 [26.3 独立参考](java263-reference.md)。标题与名称的局部原点分别为 `(30,7)` 和 `(30,18)`，前进宽度为 54 和 27 GUI 像素，均无阴影。在 960×540 的应用取帧中，一个 16×16 Unihex 源像素对应一个输出像素。按原版原点而非事后移动位置，与独立解出的字体位图逐点比较：标题匹配 325/325，名称匹配 141/141，两行均无多余像素。**旧缓存的 BDF 即便不缺笔画，也不是这套字形**，不能用后备字体的测试替代这个对照。

遮开文字与图标后，面板取样的 4,314 个不透明点与原版面板 PNG 无颜色差异；钻石正面取样的 480 个不透明点与对应物品 PNG 无颜色差异。以上分别是实际应用画面对原版绘制参数、字形和源贴图的比对，不是游戏最终帧缓冲对拍。方块和特殊物品的已知边界另见 [Java 图标核查](java-toast-icon.md)。

### 缺少原版中文字库时的第 52 帧

使用本机已下载的 26.3 资源（无资源包、未补齐 Unihex），在独立数据目录打开 Java 经典样式，手动 GUI 缩放 4，60 fps，定位第 52 帧。旧版使用内置 BDF 时，把小数采样坐标当成了源位图的字节位置：“进度已达成！”仅绘出 121 个着色像素，“钻石！”仅绘出 52 个；只测文字的外接矩形不能发现断笔。

修正后，在 480×270 取样画面中，将两行的着色像素分别与 BDF 原始逐行位图对齐：匹配 244/244 和 104/104，没有缺笔或多笔。按相同参数导出含透明首末帧的 373 张 PNG，第 52 帧解码后的 RGBA 与同设置静帧逐字节相同。这里验证的是后备字体的完整性，不表示后备字形等同于 Mojang 字形。

同一旧工程的自动节拍采用原版时，阶段轨和属性栏均显示实际生效的 0.60／5.00／0.60 秒，总长 6.20 秒。原先保存的 0.25／2.50／0.25 秒没有被改写；切到自定义时才恢复可编辑时长。也验证了切回原版、撤销、以及合成中同模板不同实例不会共用错误的阶段数据。

2026-11-18 在 Windows 桌面应用里，以同版本的已授权 26.3 资源栈、默认 GUI 缩放 4、60 fps 取 480×270 透明帧。以 alpha ≥ 128 统计面板左边界：片段 0.300、0.600、5.900 秒分别为 **440、320、360**，与上表原版 JVM 的进入中点、全显、退出中点相符。这是应用渲染与原版位置值的对照，不把本次 PNG 当成游戏录屏，也不是对每个字形或颜色的验证。

`tests/unit/T-FID.java-toast.test.ts` 用合成输入验证年代裁区、固定尺寸、文字坐标、换行/透明度、毫秒位置、乱序取样、音效 cue、兼容设置和缺图行为；也核对了混排的实际 CPU 栅格、基线边界与量字不创建贴图。模板用 `ctx.text.measureGui` 排版，仅为最终显示的行栅格化文字。未比对所有自定义字体、字符整形或双向文字；图标仍用模板物品句柄，不模拟物品模型覆盖、附魔闪烁或游戏的 GUI 灯光。没有采集实际原版游戏帧或原版现场声音，不声称像素/音频逐帧同一、实机录屏验收或剪辑软件回读通过。没有将本次证据所用的 Mojang 文件加到仓库、测试夹具或安装包。
