# Java 进度提示的图标、面板与顺序

## 核对结果

对照本机 1.21.1 正版 JAR 和 26.3 缓存 JAR，只读条目并在内存解码。JAR 与映射来源见 [Java 提示证据](java-toast.md)。没有用游戏画面或二进制素材作仓库夹具。

| 项目 | Java 1.21.1 和 26.3 的测量值 |
| --- | --- |
| 面板 | `textures/gui/sprites/toast/advancement.png` 两版字节相同，SHA-256 `15a959d338d8ce98c1381f95d34f7143377669bcadae1198900bea88144d6634`。160×32，18 个透明像素，5102 个不透明像素；左上 `(0,0)` 透明，`(8,8)` 为 `(33,33,33,255)`。无需换图或改尺寸。 |
| 钻石贴图 | `textures/item/diamond.png` 编码文件不同，但解码后的顶行优先 RGBA8 完全相同（256 个像素无差异，SHA-256 `c23086436b8d1a96b592109ece2a4050865e66b2b1dab9aec28d1031da3f1068`）。120 个不透明像素，不透明包围盒为左闭右开 `(2,2)–(14,15)`；源 `(8,8)` 为 `(161,251,232,255)`。 |
| 钻石模型 | 两版的 `models/item/diamond.json` 都用 `item/generated` 和单层 `item/diamond`，无 GUI 特殊变换，生成模型使用 `gui_light: front`；26.3 的 `items/diamond.json` 是直接模型引用，不是条件、组合或动态选择。 |
| 摆放与顺序 | 1.21.1 的提示绘制和 26.3 的提取均依次提交面板、文字、图标；`fakeItem` 左上 `(8,8)`，GUI 单位宽高均为 16。首槽停在右上角。480×270 GUI 全显时，面板左上 `(320,0)`；图标盒 `(328,8)–(344,24)`；钻石的可见像素范围为 `(330,10)–(342,23)`。 |

用本机 `javap` 读取 1.21.1 的 `fks`、`fhz`（分别是 `AdvancementToast`、`GuiGraphics`）及 26.3 的 `AdvancementToast`、`GuiGraphicsExtractor`、`GuiItemAtlas`。用其灯向量和 GUI flat 变换求得正面两光源的正点积约为 `0.959726`、`0.096568`，在 `0.4 + 0.6 × sum` 之后钳到 `1.0`。项目的 `item().single()` 虽为挤出网格，但默认相机正交向 `−Z`、图标无旋转，侧壁在投影中面积为零，正面顶点色为白。另将两版 JAR 的钻石 PNG 分别在内存传入实际 `EngineResources` 和 `createItemHandle`，沿 `−Z` 对 16×16 个像素中心取最近正面交点，经 UV 读取 RGBA：两版分别为 256/256 匹配。因此默认钻石保留原句柄，不猜 `gui/sprites` 下有物品图，也不复制静态精灵。两版绑定的是同一资源 ID；只读取已选资源栈，不能由样式 ID 推断用户实际绑定的版本或资源包内容。

## 修正及验证

- 方块先前以未旋转的正面贴满 16×16。两版的钻石块、石头、圆石、泥土、橡木木板、橡木原木和熔炉继承同一个 `models/block/block.json` GUI 姿态：`XYZ` 旋转 `(30°,225°,0°)`、缩放 `0.625`、零偏移。Java 进度档只对这些已核实 ID 应用姿态，仍使用 SDK 的六面网格。用无窗口 JShell 调用 1.21.1 的 `ggh`、`fbi` 和 26.3 的 `ItemTransform`、`PoseStack`：相对于图标中心，投影水平范围约 `[-7.071,7.071]`，垂直范围约 `[-7.866,7.866]`。26.3 的类接收 `0…1` 模型坐标，旧类的探针用居中的 `−0.5…0.5`，两者结果相同。项目仍使用自己的方块面色和贴图映射，不宣称原版库存光照、动态模型、特殊装备或资源包模型覆盖像素一致。
- 原先实体图标进入 Three 的不透明队列，早于透明面板与文字；现在 Java 进度单独在同一队列按面板 → 文字 → 图标排序，保留深度测试和方块内部遮挡。文本子网格只改排序，不动文字内容、几何或字形。面板、旧成就和 `generic` 不换资源；特殊物品仍用原 SDK 路径及其缺失诊断。例如盾牌在 26.3 是条件模型，不假设存在可直接渲染的平面 PNG。
- `tests/unit/T-FID.java-toast-icon.test.ts` 对两种进度档分别用合成 RGBA 逐一核对图标盒 256 个像素中心的几何／UV／源颜色，检查面板路径与绘制状态、钻石块 8 个投影角点，以及特殊物品不走臆测的静态资源。这里的逐像素结果是 CPU 取样，不是 Electron 游戏帧；原版证据为 PNG、模型元数据及独立 JVM 数值，不是原版实机录屏或导出回读。
