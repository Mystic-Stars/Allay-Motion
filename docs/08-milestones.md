# 08 里程碑

按顺序做。每个里程碑结束的条件都一样：

1. 该里程碑列出的验收测试全部通过，测试按文档里的编号命名（例如 `T-ENG-1`）。
2. `pnpm check` 全绿。
3. `docs/review/M<n>/` 里有这一阶段的截图或录屏，以及一段不超过半页的说明：做了什么、哪里和规格不同、还有什么没验证。
4. 所有偏离规格的地方记在 `docs/decisions.md`：偏离了什么、为什么。
5. 里程碑里标了“人工确认”的事项已经交给人，并说清楚要人看什么。

验收测试没过就不开始下一个里程碑。

## M0 脚手架与安全基线

**目标**：一个空壳应用，外观和安全设置已经是最终形态。

- pnpm workspace；TypeScript 严格模式；ESLint（含依赖方向规则）；Vitest；Playwright。
- electron-vite 搭起主进程、preload、渲染进程；`app://` 协议；内容安全策略；会话级网络拦截；加固的 `webPreferences`；fuses。
- 无边框窗口加系统窗口按钮；窗口位置和大小的记忆。
- Tailwind CSS 4；`shadcn init -b base`；写入 `06-ui-design.md` 6.2 的全部设计变量和两套主题。
- 三栏加播放条的空布局，分栏可拖、可折叠、可记忆。
- i18next 骨架（两种语言）；设置的读写；日志。
- `scripts/check-provenance.ts`、`scripts/check-licenses.ts`；CI。
- `pnpm dist` 能产出安装包。

**验收**：T-ARC-1、T-ARC-2、T-ARC-3（渲染进程部分）、T-ARC-6、T-UI-6、T-UI-8。

## M1 竖切：从模板到带透明通道的文件

**目标**：用最少的界面，把整条链路打通并证明它是对的。这是全项目风险最高的一步，不要在这里省测试。

- 引擎 Worker、Comlink 协议、看门狗。
- 完整的帧管线：子帧累积、三种 resolve 模式（`02-engine.md` 2.6）。
- 舞台与相机；`ctx` 里的 `THREE`、`params`、`stage`、`random`、`noise2D`、`ease`、`math`、`time`。
- 一个临时的、写死的方块擦除模板，贴图用代码生成的占位图，经一个桩实现的 `resolveResource` 传入。
- 预览画布，以及播放、暂停、拖动。
- `pnpm ffmpeg:fetch`；导出任务的主进程实现；PNG 序列和 ProRes 4444 两个预设，命令行照 `05-export.md` 5.3。

**验收**：T-ENG-1 至 T-ENG-5；T-EXP-1（①②）、T-EXP-2、T-EXP-3（①）、T-EXP-5、T-EXP-6、T-EXP-7（此时用临时模板代替 T1）；T-ARC-3（Worker 部分）、T-ARC-4、T-ARC-5。

**人工确认 H-M1**：把导出的 MOV 放进一个真实的剪辑软件，叠在素材上方。请人看三点：半透明边缘有没有黑边或白边；颜色和预览是否一致；片段首尾有没有突然出现或消失。

## M2 素材

**目标**：不依赖任何外部文件就有完整的 Minecraft 风格素材；资源包和本机游戏能改变画面。

- `pnpm assets:gen`：方块贴图、物品贴图、界面贴图、合成音效。
- 方块目录、物品目录、名称表、着色常量。
- 资源层的四种实现（内置目录、zip、文件夹、游戏 jar 加资源索引）；资源栈解析；`resourceStamp`。
- 从主进程到 Worker 的资源通路和缓存。
- `.mcmeta` 动画贴图。
- 方块与物品的网格（面明暗、着色、逐实例的不透明度和染色）；精灵与九宫格。
- 文字对象逐字解析已授权资源层的字体提供器：先用所选字体，再试 `minecraft:default`，最后用本机系统字体。无资源时仍可预览和导出，不下载字体。
- 缩略图的批量生成和磁盘缓存。
- 本机 Minecraft 的探测；首次发现时的对话框；资源栈弹层（功能完整，外观可以粗糙）；拖入资源包。

**验收**：T-AST-1 至 T-AST-7；覆盖率检查；来源登记检查。

**人工确认**：H-ART（自制贴图和物品像素画的质量）。如果这台机器上装了游戏，请人顺便确认开关原版层时预览会变。

## M3 模板系统

**目标**：模板成为可安装、可校验、可派生的包；内置模板走的是公开接口。

- `template-sdk`：manifest 的 schema、15 种参数类型、参数校验、迁移框架。
- 模板包的读取、安装校验流程（`04-templates.md` 4.8）、卸载。
- `pnpm templates:build`；应用从 `resources/templates/` 装载内置模板。
- 预设和派生模板的存取与装载。
- 把 M1 的临时模板重写成正式的 T1，包含全部参数。

**验收**：T-TPL-1、T-TPL-2、T-TPL-6、T-TPL-7、T-TPL-8；T1 通过 T-TPL-3、T-TPL-4、T-TPL-5。

## M4 界面

**目标**：`06-ui-design.md` 描述的完整界面。悦灵相关的位置先用占位图形，但组件接口已经是最终的。

- 顶栏、模板库（卡片、封面和悬停预览的生成）、预览视口（背景模式、参考线、错误卡片）、播放条（色段、可拖的分界线、剪辑点标记）、属性面板。
- 全部编辑器专用控件；由参数定义生成属性面板。
- 撤销重做；快捷键；命令面板；设置对话框；工程的新建、打开、保存。
- 两种语言的全部文案；两种主题；加载、空、错误各状态。
- `Allay`、`AllayLoader`、`AllayProgress`、`AllayEmpty`、`AllayHead` 的接口和占位实现，包括加载时序逻辑。

**验收**：T-UI-1 至 T-UI-8；T-ALY-2、T-ALY-5（用占位图形即可验证时序和点击穿透）。

## M5 悦灵

**目标**：悦灵成为应用的一部分。

- 模型、贴图、四个动作，写成内部模板。
- `pnpm mascot:bake`：图集、头像、应用图标、联络图。
- 把占位实现换成真正的组件；四段编排；十一个出场位置；减少动效的替代表现。
- 启动画面窗口。

模型、贴图、烘焙这三项只依赖 M1，可以提前到 M1 之后任何时候做，好让人尽早看到样子。

**人工确认 H-ALY**：先交联络图和三段编排的录屏，确认后再接到全部位置。

**验收**：T-ALY-1 至 T-ALY-7。

## M7 导出完善

**目标**：导出对话框和四个预设都是最终形态。

- 导出对话框的设置页、进度页、完成页；`AllayProgress` 接入真实进度。
- 透明 WebM 和绿幕 MP4 两个预设；编码器探测与缓存。
- 画质档位和快门角；离线混音；遮盖检查；文件命名；体积估算。

**验收**：T-EXP-1 至 T-EXP-9 覆盖全部四个预设；六个内置模板各以 1080p60 标准画质导出一次并通过自动检查。

**人工确认**：请人把四种格式各导一个，放进自己常用的剪辑软件试一遍，记下哪个软件认哪种格式。结果写进导出对话框里各格式的“适用于”说明。

## MD 模板开发模式（2026-11-13 用户确认纳入，原“之后的方向”第 1 条）

**目标**：写模板的人用自己的编辑器改模板文件，应用自动刷新预览。不含任何内嵌编辑器或 MCP；方案与解耦要求见 `docs/code-editing-and-mcp-plan.md`。

- 主程序侧的准备（该文档第 4 节 H3–H6、H8–H12；H1、H2 随界面重设计完成，H7 随 M7 完成）。
- “打开模板文件夹”“从内置模板复制一份来改”；主进程监视用户模板目录，内容变化时通知界面。
- 热重载管线：防抖、静态检查、在备用 Worker 里试载并试渲当前帧，成功才切换，失败保留旧 Worker 和上一帧；保住播放位置，参数按键名和类型重新对上。
- 结构化诊断（编译、装载、setup、update、看门狗、确定性），带行号列号；错误浮层显示位置。
- 往模板文件夹写 `template-api.d.ts` 和 `jsconfig.json`，外部编辑器有补全；模板编写指南。
- 可选模块的接入点和“可拆除”检查先建好：`packages/host-api`、`packages/optional/` 的惰性发现、依赖方向规则与违规夹具、CI 里“目录为空或被删时 `pnpm check` 照常通过”。此时 `packages/optional/` 下没有任何模块。

MD-a（不碰界面的部分：H5 的引擎侧、H8、H10、H12）可以与界面重设计并行；MD-b（界面接线：H3、H4、H6、H9、H11、错误浮层、命令）在界面重设计合入之后做。排在 M7 之后、M8 之前完成。

**验收**：T-DEV-1 改动模板文件后预览在时限内更新且播放位置、参数不变；T-DEV-2 写入语法错误、运行时错误、死循环、不确定代码各一次，分别得到带位置的对应诊断，预览保留上一帧，修好后恢复；T-DEV-3 `template-api.d.ts` 与 template-sdk 的类型一致（生成物比对），用它对内置模板源码做类型检查通过；T-DEV-4 可选模块目录不存在时全部检查通过，故意让核心包引用可选模块的夹具被 lint 拦下；此前的验收测试继续通过。

## 动画工作台增量（2026-11-18 用户确认）

**范围**：原单模板工作流和 T1–T6 保留。工作台增加最长 5 分钟的多轨合成与片段变换关键帧，模板保持纯代码，不做可视化模板编辑或视频导入；仅适配本地普通未加密基岩资源包。玩家皮肤可本机导入，按 Java 正版玩家名获取公开皮肤是需要逐次同意的主进程官方查询（`09-compliance.md` 9.10）。

**验收**：原有 T1–T6 动效与像素基准不变；两个新增模块都纳入 `T-DEV-3` 与内置包复制检查。工作台和新模块按 `T-STUDIO`、`T-STUDIO-OBJ`、`T-EXP-COMP`、`T-AST-VERSION`、`T-SKIN` 的专项用例验收；模拟五分钟写帧不等同于实际编码或剪辑软件回读。

- `T-STUDIO-CODE-1`：两个原生窗口；代码窗跟随主窗选中的片段，两份同模板实例不串参数；撤销、实际播放、拖帧、关窗重开后主预览仍可用。
- `T-STUDIO-CODE-2`：合成中可把选中的内置实例转为脚本副本；保存走共享模板确认和备用 Worker，失败不改磁盘、保留草稿与主预览。

## 之后的方向（不在这次交付内）

按价值排序，供以后规划：

1. （已纳入本次交付，见 MD）模板开发模式：监视一个文件夹，脚本一改就热重载，方便写模板的人。
2. （已限范围纳入，见动画工作台增量）在一个工程里叠放多个模板片段，各有起始时间。
3. 合成模式：导入前后两段素材，做“画面碎成方块”这类需要原画面的转场。
4. 可视化模板编辑器：编辑模板内部逻辑，不是工作台已有的片段变换关键帧。
5. 读取资源包自带的模型；支持旧版资源包命名。
6. macOS 和 Linux 的安装包。
7. （已于 0.1.2 加入，见 `docs/decisions.md`“自动更新”）自动更新。
