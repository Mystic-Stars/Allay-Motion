# 09 合规：素材、品牌、许可

本文不是法律意见。它记录的是 2026-11-13 查到的事实、本项目据此定下的规则，以及必须由人拍板的事项。

## 9.1 三条底线

1. **仓库和安装包里没有 Mojang 的任何文件**：贴图、音效、字体、模型、官方图片都不行。
2. **产品不能显得是官方的**，也不能显得得到了 Mojang 或 Microsoft 的认可。
3. **每一个第三方素材都有来源和许可记录**，没有记录的文件进不了仓库。

## 9.2 Mojang 的规则说了什么

来源：Minecraft 最终用户许可协议（`https://www.minecraft.net/en-us/eula`）和 Minecraft 使用准则（`https://www.minecraft.net/en-us/usage-guidelines`），查阅的是 2026 年 11 月 11–12 日的版本。以下是转述，以原文为准。

**许可协议**

- 可以开发工具、插件和服务，前提是它们不显得是官方的或被认可的，比如不使用官方的 logo。
- 不得分发 Mojang 制作的任何东西，把游戏软件或内容的副本给别人就算分发。
- 你原创的东西归你；Mojang 的财产和作品的复制品、派生物归 Mojang。

**使用准则**

- 三个定义都很宽：
  - “名称”包括游戏、标语、**功能特性**、活动的名字，以及与之容易混淆的名字。
  - “品牌”包括名称、logo、**字体**、贴图，以及游戏任何部分的**显著特征**。
  - “素材”包括游戏里的代码、图形、贴图、图片、模型、声音，以及游戏的截图和视频。
- 名称、品牌、素材**及其派生物**的所有权利归 Mojang 和 Microsoft。
- “Minecraft”可以出现在产品的副标题或描述里，条件是它不是名称的主体，并且产品的品牌形象（包括 logo）里不使用其品牌或素材的任何其他部分。
- 不能把其名称用作产品名的主体。
- 只要与他人分享，不管收不收钱，都按“商业使用”对待，没有“免费工具可以例外”的说法。
- 必须在产品、介绍页、网站等处醒目地放上非官方声明（原文见 9.5）。
- 准则没有覆盖的用法，默认是不希望你做的，要做就先取得书面许可。

## 9.3 对本项目各件事的判断

| 事项 | 判断 | 处理 |
|---|---|---|
| 安装包内置原版贴图、音效、字体、模型 | 明确不允许 | 不做。用三层资源栈（`03-assets.md`） |
| 读取用户本机已安装的游戏文件 | 不涉及分发 | 只读、不复制、不上传；首次使用前询问一次 |
| 导入本机普通未加密基岩资源包与皮肤 PNG | 仅用于用户自己的本机创作 | 不上传、不随仓库或安装包分发；不执行资源包内代码，不解密或读取模型 |
| 用户导出的视频里出现 Minecraft 素材 | 这是用户自己的视频创作，适用准则里关于视频内容的条款 | 在关于页给出准则链接，不替用户做判断 |
| 品牌字标、菜单、首次启动引导和编辑器控件使用游戏字或仿游戏字 | 游戏字体属于其品牌 | 不用。界面使用系统 UI 字体，代码使用系统原生等宽字体 |
| 作品内容或明确的字形样张使用游戏字形 | 来源限于用户已授权并启用的资源层 | 仅在相应资源许可范围内使用；不新增样张界面 |
| **用悦灵做 logo 和吉祥物；用 Allay / 悦灵做产品名** | **准则不支持，有风险** | 见 9.4，必须由人决定 |

## 9.4 品牌决定（H-BRAND）

项目负责人的意图是：产品叫 Allay Motion（悦灵动画），logo 和吉祥物是 Minecraft 的悦灵。把查到的事实对上去：

1. 悦灵是游戏里的一种生物。准则对“名称”的定义包含功能特性的名字，而其名称不能用作产品名的主体。“Allay”同时是一个普通的英文单词，“悦灵”则是专为这种生物造的译名，后者更难说成巧合。
2. 悦灵的形象是游戏的显著特征，落在“品牌”的定义里。准则要求提及 Minecraft 的产品不得在 logo 里使用其品牌或素材。而本产品必须在描述里提及 Minecraft，否则说不清它是干什么的。
3. 自己画的悦灵仍然是这个角色的派生物。**自绘能避免“分发官方文件”，不能避免“用其角色做品牌”。**
4. 以游戏里的生物命名、用重绘的生物做图标的社区工具并不少见。这说明存在先例，不构成许可。

三条路：

| 方案 | 做法 | 风险 |
|---|---|---|
| **A** | 按原意图：名称不变，吉祥物是自绘的悦灵 | 名称和形象都在准则限制的范围内；可能收到更名或下架的要求 |
| **B** | 名称不变；吉祥物改成一个明显原创的角色（受悦灵启发的蓝色小精灵，但比例、五官、翅形都不同，有自己的名字） | 形象风险大幅降低；名称风险仍在 |
| **C** | 名称和形象都换成原创 | 最低 |

**默认按 A 实现**，因为这是负责人的明确意图。但有三个条件：

- **对外发布之前，必须由人确认 H-BRAND。** 选 A 的话，建议同时给 Mojang 写信申请书面许可，准则本身就是这么要求的。
- **工程上保证能在一天内切换到 B 或 C。** 所有品牌资产只存在于 `packages/mascot` 和 `packages/ui/src/brand/`（产品名、字标、图标）。应用其余部分只通过组件和 `brand.*` 文案键引用它们，不得把产品名或“悦灵”写死在别处的用户可见文字里。包名、模板 ID 前缀、文件扩展名里的 `allay` 属于内部标识，换品牌时不必改。
- **无论选哪条路，下面这些都要做到：**
  - 产品名里不出现 “Minecraft”，它只出现在副标题和描述里。
  - 不使用 Minecraft 的 logo、字标、官方美术图，不使用模仿其字体的字体。
  - §9.3 允许在作品中使用已授权的游戏字形，不等于授权将其用于产品字标、菜单、启动页或官网标题；切换语言或启用资源包都不改变这条边界。见[现行字体决策](decisions.md)。本次字体变更不代替 H-BRAND 的人工确认。
  - 关于页、安装程序、启动画面、项目主页和仓库说明都带非官方声明。
  - 不拿含有这个形象或名字的东西去注册商标，不卖周边。
  - 应用免费。如果以后打算收费或接受赞助，先回到本节重新评估。

另外，没有对 “Allay Motion” 做过重名和商标检索（检索需要把名字发到外部服务，没有擅自做）。发布前由人查一下（H-NAME）。

## 9.5 非官方声明

准则给出的措辞，括号里按产品类型填：

> NOT AN OFFICIAL MINECRAFT PRODUCT. NOT APPROVED BY OR ASSOCIATED WITH MOJANG OR MICROSOFT.

- 英文界面用上面这句；中文界面在它下面加一行中文：“本软件不是 Minecraft 官方产品，未经 Mojang 或 Microsoft 批准，也与它们无关。”
- 位置：关于页（完整显示）、启动画面底部（小字）、安装程序的欢迎页、仓库 `README` 的开头、任何下载页。
- 文案键 `brand.disclaimer`，由 `packages/ui/src/brand/` 统一提供。

## 9.6 素材来源登记

- 仓库根目录的 `ASSETS_PROVENANCE.json` 登记每一个（或每一组）二进制素材：

  ```json
  [
    { "path": "resources/builtin-pack/**", "origin": "generated", "generator": "scripts/gen-builtin-pack.ts", "license": "项目自有" },
    { "path": "packages/mascot/assets/**", "origin": "generated", "generator": "pnpm mascot:bake", "license": "项目自有" }
  ]
  ```

- `scripts/check-provenance.ts` 在 CI 里运行：仓库里任何图片、音频、字体、压缩包如果没有被某条记录覆盖，就失败。
- 同一个脚本拒绝这些情况：路径里出现 `assets/minecraft/` 却不在 `resources/builtin-pack/` 或测试夹具目录下；扩展名为 `.jar`；文件名与原版贴图同名、内容却不是由生成脚本产出的（用“重新生成后逐字节比对”来判断）。
- 测试夹具里的“资源包”和“游戏目录”全部用脚本生成的假数据，不放真实的游戏文件。

## 9.7 第三方素材与字体

许可情况是 2026-11-13 查到的，引入前再核对一次。

| 名称 | 许可 | 结论 |
|---|---|---|
| Pixel Perfection（XSSheep 的原版） | CC BY-SA 4.0 | 许可没问题，但只到 1.11，是旧的文件命名，不能直接用 |
| Pixel Perfection Legacy（延续版，覆盖到当前版本） | 各处标注不一致：一个平台标 CC-BY-4.0 却链接到 BY-SA 的条文，另一个平台标“自定义许可”，仓库里没有许可文件，还有多位贡献者 | **引入前必须由人向维护者确认并留存书面答复**（H-PACK） |
| ProgrammerArt（deathcap） | CC BY 4.0 | 只到 1.9 的命名，不适用 |
| Faithful、Bare Bones、Unity 等常见资源包 | 自定义许可、保留所有权利或禁止商用 | 不能内置 |

桌面与官网不分发或下载文字字体，也不单独导入用户字体文件。作品可读取授权资源包中的字体提供器；逐字回退及旧工程兼容规则见 `03-assets.md` 3.9。

- 界面图标用 Phosphor（`@phosphor-icons/react`，MIT），代码依赖，走 9.8 的许可检查；不自绘图标。
- 内置层默认是项目自制的程序化贴图，**不依赖上表中的任何资源包**。并入开放许可的资源包只是提升画质的可选项。
- 采用 CC BY-SA 的素材意味着：署名；对这些贴图的改动版本要以相同许可发布。通常的理解是，把它们作为素材集合打进应用不会改变应用代码的许可。
- 所有第三方素材的署名和许可全文显示在“关于 → 第三方许可”，并随安装包附带。

## 9.8 代码依赖的许可

项目自己的许可证：用户已定（2026-11-14）为 **GPL-3.0 + 商业授权**（`GPL-3.0-only`，见 README 的“许可”一节和 `docs/decisions.md` M8）。依赖因此必须**同时兼容 GPL-3.0 和将来的商业授权**：版权人要能把整个应用以非 GPL 的条款另行授权，所以仍然不得引入 GPL、AGPL 的第三方依赖。允许列表不变：

- 允许：MIT、BSD、ISC、Apache-2.0、0BSD、Zlib、CC0。生产依赖不引入文字字体包。
- 不允许进入应用包：GPL、AGPL、SSPL，以及任何带“禁止某类用途”条款的许可。
- LGPL 只允许一处：以独立进程调用的 FFmpeg。
- `scripts/check-licenses.ts` 在 CI 里扫描生产依赖，遇到不在允许列表里的许可就失败。

两个已知的坑，都不要用：

- **GSAP**：免费，但其标准许可禁止把它用在“让用户不写代码就能做可视化动画、并与 Webflow 的动画功能竞争”的工具里，除非取得书面同意。
- **Theatre.js**：`@theatre/studio` 是 AGPL-3.0。

关键帧和缓动的求值自己写，见 `02-engine.md` 2.9。

## 9.9 FFmpeg

- 发行渠道：FFmpeg-Builds（`github.com/FFmpeg-Builds/FFmpeg-Builds`，即原来的 BtbN/FFmpeg-Builds）。
- 变体：`win64-lgpl`，取发布分支的构建（查到的最新是 n9.0），不用 master。在 `scripts/fetch-ffmpeg.ts` 里固定到具体的发布标签并写死 SHA-256。
- 这个变体启用了 version3，许可是 **LGPLv3**。分发时：随包附上许可全文；在“关于”里写明所用构建的来源、版本和取得源码的方式；`ffmpeg.exe` 作为独立文件放在资源目录，用户可以自行替换。
- 查到该变体的构建脚本启用了 `libvpx`、`libopenh264`、NVENC、AMF、QSV（libvpl）；`prores_ks` 是 FFmpeg 自带的。`h264_mf` 在不在没有实测，以 `ffmpeg -encoders` 为准。
- H.264 涉及专利许可。硬件编码器和系统编码器（NVENC、QSV、AMF、Media Foundation）由硬件或系统厂商负责；自行编译进去的 `libopenh264` 不在 Cisco 为其官方二进制提供的专利许可覆盖范围内。所以探测顺序把它排在最后。是否保留这个兜底，由人决定（H-H264）；不保留的话，没有可用硬件或系统编码器的机器上“绿幕 MP4”预设会被禁用。

## 9.10 隐私与网络

- v1 没有账号、遥测、崩溃上报、在线素材库。已有的联网例外为用户触发的原版素材下载（`docs/decisions.md` M2a）和自动更新（`docs/decisions.md`“自动更新”：只读本仓库 GitHub / GitCode 的 Release，不带用户信息，可在设置里关闭）。
- 另经用户明确批准：仅在用户主动“按 Java 正版名获取皮肤”并在主进程对话框同意当次发送该玩家名后，查询公开 Java 档案并下载该皮肤。主进程仅用固定 HTTPS GET 路径访问 `api.mojang.com`、`sessionserver.mojang.com` 和 `textures.minecraft.net`，不跟随跳转；拒绝即不查询。不登录、不上传文件、不后台查询，不查询基岩或 Xbox 账号。皮肤只存本机库，不进仓库或安装包；授权不是对 Mojang 条款的确认，仍按 `docs/decisions.md` 的 H-DOWNLOAD 核对。
- 渲染进程的网络访问在会话层被拦截（`01-product-architecture.md` 1.6）。
- 日志只写在本机的应用数据目录。“复制诊断信息”由用户自己决定发给谁。
